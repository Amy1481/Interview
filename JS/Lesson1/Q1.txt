1.Compare internal and external JavaScript.

| Feature           | Internal JavaScript                                                  | External JavaScript                                                                                     |
| ----------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Definition**    | Code is written directly inside the `<script>` tag in the HTML file. | Code is written in a separate `.js` file and linked to the HTML using the `<script src="file.js">` tag. |
| **Location**      | Inside `<head>` or `<body>` of HTML.                                 | Stored outside HTML in a separate file.                                                                 |
| **Advantages**    | - Quick to write small scripts.<br>- Good for single-page scripts.   | - Keeps HTML clean.<br>- Reusable across multiple pages.<br>- Easier to maintain for large projects.    |
| **Disadvantages** | - Makes HTML bulky.<br>- Harder to maintain for large scripts.       | - Extra HTTP request (can be optimized).                                                                |
| **Example**       | `html <script> alert('Hello'); </script> `                           | `html <script src="script.js"></script>` and in `script.js` → `alert('Hello');`                         |

Internal is good for small tasks; external is preferred for larger, reusable code.

2.How does the browser load and execute JavaScript?
Browsers handle JavaScript in 3 main steps:
a)Browser reads HTML from top to bottom.

b)When it finds a <script> tag:
  -Internal script → Executes the code immediately.
  -External script → Downloads the .js file, then executes it.

c)After execution, the browser continues loading the rest of the page.

💡 Important points:

Scripts can stop the page from loading until they run (default behavior).

To avoid blocking:
  -Use <script defer> → waits until HTML is fully loaded, then runs scripts.
  -Use <script async> → downloads in parallel and runs as soon as it’s ready (order may change).

3.Why does script order matter?
JavaScript runs from top to bottom in the order it appears in the HTML.

If a script uses a function or variable that is defined in another script, the script with the definition must come first.

If the order is wrong, the browser will show an error like ReferenceError because it can’t find the function or variable yet.

Example:

<script src="first.js"></script>  <!-- defines function sayHi() -->
<script src="second.js"></script> <!-- uses sayHi() -->


Works ✅ because first.js runs first.

<script src="second.js"></script> 
<script src="first.js"></script> 


❌ Will cause error because sayHi() is not defined when second.js runs.

Key Point:

Always load scripts in the correct order to ensure dependencies work.

4.Explain how errors are displayed in the console.
When something goes wrong in your script, the browser shows errors in the console (press F12 → Console tab):

Syntax Errors: Mistakes in the code structure.

Example: if( { console.log("Hi"); } → Missing parentheses → SyntaxError.

Runtime Errors: Code is correct, but fails when executed.

Example: undefinedFunction() → ReferenceError: undefinedFunction is not defined.

Logical Errors: Code runs but behaves incorrectly.

These don’t show errors directly, but console can help debug with console.log().

Error format in console:

ErrorType: Description
at file.js:lineNumber:columnNumber


💡 Tip: Using console.error("Message") helps highlight errors in red.

5.What is ECMAScript?
ECMAScript (ES) is the standard specification that defines how JavaScript should work.

JavaScript is the implementation of ECMAScript.

Each version of JavaScript (ES5, ES6/2015, ES7, …) follows ECMAScript rules.

Key points:

ECMAScript defines:

Syntax (how code is written)

Types (Number, String, etc.)

Statements (if, for, while)

Keywords and reserved words

Objects and functions

Browser and engines (V8 in Chrome, SpiderMonkey in Firefox) implement these standards.

💡 Example: ES6 introduced let, const, arrow functions, template literals, etc. – features that older versions (ES5) didn’t have.
